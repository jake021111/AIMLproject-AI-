[INT8 결론 - 측정으로 확정]
 Linux 컨테이너에서 full-integer INT8 변환 성공시킴.
 (원인: Ultralytics AutoUpdate 가 런타임 pip install 로 torch 를 깨뜨림
  -> 의존성 사전설치 + YOLO_AUTOINSTALL=false + litert-torch 추가로 해결)

 그런데 정확도 측정 결과 채택하지 않기로 함 (test 156장 기준):
   best.pt        mAP@0.5 0.826  (기준)
   hybrid INT8    mAP@0.5 0.816  손실 1.2%   <- 채택
   full-integer   mAP@0.5 0.713  손실 13.7%  <- 탈락
 CLAUDE.md 7.4 의 "손실 5% 초과 시 hybrid fallback" 규칙 적용.
 full-integer 는 클래스 점수가 25단계로 뭉개짐(hybrid 는 12만단계).
 덤: hybrid 는 NHWC 라 문서 계약 그대로 -> 프론트 수정 0.
